Task 2: Refined ROS2 Telemetry and CPU Resource Allocation

Make robot faults visible.

Telemetry uses the validated client-to-hub and hub-to-all-clients path, with a refined runtime view for deciding how telemetry work should share CPU resources with the rest of the system.

Refine

Telemetry work is treated as a runtime workload that must be allocated without obscuring control and communication paths.

React

Every subscribed client can display, log, or use the event in its next decision.

Message contract

One shape for a meaningful event.

{
  "kind": "telemetry",
  "user_id": "user-2",
  "code": "FORMATION_LOST",
  "text": "Robot left formation"
}
Transport decision

Reuse the broadcast path.

A second transport would add another failure mode. Reusing the hub keeps telemetry visible to every client.

Resource decision

Protect the control path.

Telemetry processing must be visible as a workload so CPU allocation can be reasoned about alongside communication and robot control.
