Telemetry / Fleet view

Make robot faults visible.

Telemetry uses the same validated client-to-hub and hub-to-all-clients path as Task 1 messages. That keeps the transport simple while extending the meaning of the record.

01

Detect

A client observes a robot state change, such as leaving formation.

02

Publish

The client sends a telemetry JSON record on its own outbound topic.

03

Validate

The hub checks the sender and creates the shared event record.

04

React

Every subscribed client can display, log, or use the event in its next decision.

Message contract

One shape for a meaningful event.

{
  "kind": "telemetry",
  "user_id": "user-2",
  "code": "FORMATION_LOST",
  "text": "Robot left formation"
}
Decision

Reuse the broadcast path.

A second transport would add another failure mode. Reusing the hub keeps telemetry visible to every client.

Boundary

Transport is not security.

The shared topic provides delivery, not authentication or encryption. That limitation stays explicit in the design.
