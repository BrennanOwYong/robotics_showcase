Task 1

Make group communication reliable.

Each terminal is its own ROS 2 client. The hub owns identity, routing, history, and system events.

View Task 1 architecture →
01

Hub-and-spoke

Clients do not connect directly. The hub validates one record and publishes one shared view.

02

Services for control

Registration and departure are short request/response operations, so they use ROS 2 services.

03

Topics for flow

Chat, system events, and telemetry are continuous records, so they use ROS 2 topics.

04

Explicit readiness

Process detection is followed by ROS service discovery before registration starts.
