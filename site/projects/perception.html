YOLO/TensorRT Perception

A ROS 2 lifecycle node that turns camera frames into structured detections, visual annotations, and persistent object tracks.

YOLOTensorRTOpenCVLifecycle nodes
← Back to all projects

Problem statement

A robot cannot act on raw images alone. It needs repeatable detections with confidence, class identity, geometry, timestamps, and a clear relationship to the input frame. The perception node must also start, stop, and release a model safely.

How it works

The node uses ROS 2 lifecycle transitions to configure publishers, load the model on activation, subscribe to sensor-data images, and publish detection arrays and debug annotations. The tracking variant replaces one-frame prediction with persistent ByteTrack state.

image topic → CvBridge → YOLO inference\n→ DetectionArray + ImageAnnotations\ntracking mode → persistent tracker IDs

Why it matters in robotics

Perception is a timing and interface problem as much as a machine-learning problem. A downstream planner needs stable message contracts and a way to inspect false positives, missed detections, and tracker identity. Lifecycle control also matters when GPU resources must be released or a pipeline must be restarted.

How I build it

I keep model lifecycle separate from message conversion and output publication. Parameters select the model, thresholds, topics, and annotation behaviour. The tracking node reuses the detector and changes only the prediction strategy. That keeps the system composable and avoids duplicating the ROS plumbing.
