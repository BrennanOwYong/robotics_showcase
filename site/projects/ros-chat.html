ROS 2 Group Chat

A terminal-based distributed system that uses ROS 2 discovery, services, and topics to connect multiple operators through one hub.

ROS 2 JazzyDDSLifecycle
← Back to all projects

Problem statement

Robotic operations often need several people or processes to share status through the same middleware. The system must let clients join, receive an identity, exchange messages, receive join and leave events, and shut down cleanly without relying on a fixed network address.

How it works

The first client starts a background hub when needed. The hub exposes registration and departure services. Each client publishes records on its own outbound topic. The hub validates and broadcasts a single record on a shared topic. Clients render the record and use the assigned colour for remote users.

client → register_user service → hub assigns ID\nclient → /ros_chat/client/<id> → hub\nhub → /ros_chat/broadcast → every client

Why it matters in robotics

Robots are distributed systems. Operators, autonomy nodes, telemetry streams, and supervisors must share state while remaining loosely coupled. This project demonstrates the difference between a process lifecycle and a ROS graph lifecycle, and it uses the middleware for communication rather than treating it as a side detail.

How I build it

I separate short control requests from streaming data. Services handle registration and departure. Topics handle messages and telemetry. The hub owns identity, validation, broadcast, and history. This makes ownership clear and gives each failure path a defined place to be handled.
