Problem statement

An autonomous mission must continue when a sensor is noisy, an action fails, or a perception result is incomplete. A tree that only describes the happy path is difficult to operate and difficult to improve because it does not explain why a branch was chosen.

How it works

The mission is composed from stages such as vision startup, target selection, movement, firing, and shutdown. Behaviour-tree sequences and selectors coordinate actions. Retries and fallback paths handle recoverable failures. Locomotion actions provide setpoints, feedback, cancellation, and results to the tree.

mission root\n├─ start vision\n├─ select target / retry\n├─ move and act\n├─ stop vision\n└─ blind fallback when guided path fails

Why it matters in robotics

Autonomy is judged by behaviour under uncertainty. The same mission can succeed, fail safely, or fail opaquely. Explicit stage ownership, retry attempts, branch decisions, and action correlation make field testing more useful because an operator can connect an outcome to the decision that caused it.

How I build it

I treat observability as part of the mission design. The local analysis identifies where stage names, blackboard writes, decorators, and action results hide causal history. The next design step is a structured event model that records stage IDs, attempt IDs, branch decisions, and fallback reasons without changing the underlying control action schema.
