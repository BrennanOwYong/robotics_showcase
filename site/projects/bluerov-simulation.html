BlueROV2 Simulation

A Gazebo and ArduSub simulation stack that exposes a BlueROV-style vehicle through ROS 2, MAVROS, TF, and configurable odometry.

Gazebo SimArduSub SITLMAVROS
← Back to all projects

Problem statement

Underwater hardware is expensive and difficult to debug. A useful development environment must reproduce the interfaces that autonomy software depends on: vehicle state, command paths, coordinate frames, physics, and flight-controller behaviour.

How it works

The launch system brings up Gazebo, the BlueROV2 model, ArduSub SITL, MAVROS, the ROS-Gazebo bridge, and a robot state publisher. An odometry adapter can expose ground truth through the same downstream interfaces that a real vehicle would use.

ROS 2 command\n→ MAVROS → ArduSub SITL → Gazebo physics\n→ odometry adapter → MAVROS and TF

Why it matters in robotics

Simulation shortens the loop between software change and safe evidence. It also makes integration problems visible: wrong frame conventions, missing bridges, incorrect launch order, and stale state are system defects, not just algorithm defects.

How I build it

The launch file keeps hardware-facing boundaries explicit. World selection, GUI mode, ArduSub, MAVROS, and odometry are launch arguments. The URDF is used for state publication while the SDF model is used for simulation physics. This separation keeps visualisation, physics, and control interfaces understandable.
